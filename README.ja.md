# Fumi

[English](README.md) | 日本語

GitHub Copilot CLI を、仕事の秘書 Fumi にする。今入っているのは次の2つ。

- 会話（セッション）をまたいで覚えておく
- 教わった道具の場所を覚えて、場面に合わせて使う

入れるのは、指示の文書1つ、過去の会話を探すスキル1つ、書き忘れを見張るフック1つ。Windows と PowerShell だけで動く。

| ファイル | 入れる先 | 中身 |
|---|---|---|
| `copilot/copilot-instructions.md` | `~/.copilot/copilot-instructions.md` | 記憶の読み書きと、道具の使い方の決まり |
| `copilot/skills/session-search/` | `~/.copilot/skills/session-search/` | 記憶のログと、Copilot CLI が手元に残している過去の会話を、言葉で探す（読むだけ） |
| `copilot/hooks/fumi-hooks.json`、`fumi-hook.ps1` | `~/.copilot/hooks/` | 書き忘れの見張り。ログを書かずに2往復以上話した会話を、未記録の一覧に入れる |
| （セットアップで作る） | `~/.copilot/fumi.json` | 記憶のフォルダの場所（`{ "memory_dir": "..." }`）。指示の文書とフックが読む |

**セットアップは AI に任せられる。** このリポジトリを使う PC に置き、そのフォルダで `copilot` を立ち上げて「SETUP.md に従って、Fumi をセットアップして」と頼む。[SETUP.md](SETUP.md) に、置き場所、確かめ方、すでにあるものを壊さない決まり、更新と取り外しの手順が書いてある。本人が答えるのは、記憶のフォルダの場所だけ。

## 設計の工夫

| 工夫 | なぜ |
|---|---|
| 記憶を2段にする（毎回読む短い要約と、必要なときだけ探すログ） | 毎回読む量を一定に保つ。Hermes Agent や OpenClaw の記憶と同じ考え方 |
| よく使う知識は、ログを経ずに最初から要約（USER・MEMORY・TOOLS）に書く | 次の会話で確実に前提になる。ログに埋もれない |
| 書き忘れは、AI ではなくフックが数える | 指示に従うかどうかに頼らない。ターミナルを急に閉じても漏れない。返事を止める仕組みは使わない（できるか確かめられなかったため） |
| 書き忘れた会話は、次の会話の最初に秘書が起こす | 数えるのは機械、要約するのは AI、と役割を分ける |
| 過去の会話は、Copilot CLI がもともと残している記録から探す | 何も新しく保存しなくても、全部の会話が残っている |
| 探すのは、発言と返事だけを抜き出した写し（索引） | 作者の環境で測ると、記録の 99% 以上はツールの出力など。読む量が約 100 分の 1 になり、日本語も文の途中の言葉で当たる |
| 写しは記録より古いときだけ作り直し、消された会話の写しは消す | 増分で速い。本人が消した会話を残さない |
| 探した結果、ログの検索、会話の読み出しに、すべて上限を付ける | 件数がいくら増えても、トークンを使いすぎない |
| ログのファイルを開かせず、当たった話題だけを返す | 1年分のログでも、思い出すときに読むのは数千字 |
| 機械用の帳簿（未記録の一覧、写し）は記憶のフォルダの外に置く | 本人のノートや、そのフォルダの git を汚さない |
| 指示の文書に目印（`fumi: begin` 〜 `end`）を付ける | すでにある本人の指示を残したまま足せる。更新と取り外しはその範囲だけ |
| セットアップは決まったコマンドで行い、上書きの前に退避し、何度やっても同じ結果にする | AI に任せても、本人の設定を壊さない |
| PowerShell のスクリプトは UTF-8（BOM 付き） | Windows PowerShell 5.1 で日本語が化けないように。セットアップでも保存し直さない |
| 追加の道具（SQLite、Python など）を使わない | 何が入っているか分からない PC でも動く |

## 仕組み

記憶は、Hermes Agent や OpenClaw と同じ考え方で、毎回読む短い要約と、必要なときに探す全部の記録の2段にする。

```
記憶のフォルダ（例: Obsidian の vault の中の 秘書/。ノートとして見て直せる）
├─ USER.md            本人について。呼び方、担当、好み、働き方（60行まで）
├─ MEMORY.md          続いていること。進行中の案件と状態、決まったこと、約束、職場の事情（100行まで）
├─ TOOLS.md           使える道具の場所と、使う場面・使い方・注意（120行まで）
└─ memory/
    └─ YYYY-MM-DD.md  その日の会話のログ。話題ごとに要点・決まったこと・次にやること
```

| いつ | 秘書がすること |
|---|---|
| 会話の最初 | `USER.md`、`MEMORY.md`、`TOOLS.md` と、直近3日分のログの見出しと「次にやること」を読む。続きなら一言だけ言う |
| 依頼を受けたとき | `TOOLS.md` から場面に合う道具を選んで使う。使う前にそこにあるか確かめる。「確認してから」の道具は、本人が「いいよ」と言ってから |
| 「〇〇は △△ にある。〜のときに使って」 | そこにあるかと使い方（`--help` など）を確かめて、`TOOLS.md` に書く |
| 「前に」「あの件」と言われたとき、その会話で初めて出た作業名などで前の経緯が要るとき | `session-search` の `-Memory` でログを探し、当たった話題だけを読んで答える。日付を添える。見つからなければ推測しない |
| 決まった、分かった、頼まれた、一区切りついたとき | その場で今日のログに追記する（会話の終わりを待たない） |
| 会話の最初（書き忘れがあったとき） | フックが付けた未記録の一覧を見て、前の会話を `session-search` で読み、その日のログに起こす |
| よく使う知識を教わったとき（「ToDo はこの md で管理している」など） | ログではなく、最初から要約に書く。場所と使い方は `TOOLS.md`、本人の習慣は `USER.md`、続いている事情は `MEMORY.md`。どこに書いたかを一言伝え、次からはその場面で言われなくても使う |
| 会話の中で、あとで続くと分かったこと（決まったこと、約束） | ログから `MEMORY.md` に上げる（一言伝えてから） |
| 「それは忘れて」 | ログと要約の両方から消す |

ログで見つからないときは、`session-search` スキルで、Copilot CLI が手元に保存している過去の会話（`~/.copilot/session-state/*/events.jsonl`）をすべて探す。Hermes Agent の「過去の会話の検索」にあたる。秘書がログを書き忘れても、会話そのものが残っているので思い出せる。

- 本人の発言と秘書の返事だけを探す（ツールの実行の記録は拾わない）。言葉を複数並べると全部を含むものだけ。今の会話は外す。
- 当たったら、その時刻の前後のやりとりや、会話の全体を読める。
- Copilot CLI の内部の形なので、更新で変わることがある。その場合は記憶のログだけになる。

### 索引について

記録の大半はツールの出力などで、作者の環境では、発言と返事は 0.7% しかなかった（17.7 MB の記録で 0.12 MB）。そこで、発言と返事だけを抜き出した写しを `%LOCALAPPDATA%\Fumi\session-index\` に持ち、それを文字列で探す。記録が写しより新しい会話だけ作り直す。

| 案 | 判断 |
|---|---|
| 毎回、記録全体を grep | 日本語は正確だが、記録が増えると比例して遅くなる |
| Copilot CLI がもともと持つ全文検索の索引（`session-store.db` の FTS5）を使う | 作者の環境では、日本語の文の途中の言葉で当たらなかった（「スキル」が索引で 0 件、実際は 2 件）。SQLite も要る |
| 自分で FTS5（trigram）の索引を作る | 2 文字の言葉（「佐藤」など）は別の探し方が要る。SQLite と更新の仕組みが要る |
| **発言と返事だけの写しを持ち、それを探す（採用）** | 日本語は grep と同じく正確。読む量は約 100 分の 1。追加の道具は要らない |

作者の環境の 50 件の会話で、前の版（毎回 grep）と出力が一字一句同じだった。速さは前の版 0.2〜0.5 秒、新しい版は写しを作る1回目 0.55 秒、2回目から 0.07 秒。写しの大きさは 206 KB。記録が消えた会話の写しは、次に探したときに消える。

## 書き忘れの見張り（フック）

秘書は指示に従ってログを書くが、話に夢中になると書き忘れる。そこで、AI を使わないフックで見張り、書き忘れた会話を次の会話の最初に起こす。

```
返事を終えるたび（agentStop）、会話を閉じるとき（sessionEnd）
  └─ fumi-hook.ps1: その会話の記録を読む
       ├─ 記憶のフォルダに書いた（edit・create、または Add-Content などの書き込みのコマンド）→ 一覧から外す
       └─ 一度も書かずに2往復以上話した → 未記録の一覧（~/.copilot/fumi-pending.json）に入れる
次の会話の最初
  └─ 秘書: 一覧の会話を古い順に2件まで session-search -All で読み、その日のログに「（あとから記録）」として起こし、一覧から外す
```

- **止めて書かせる仕組みにしない理由**: Copilot CLI の `agentStop` フックで返事を止めて続けさせられるかは、確かめられなかった。止める仕組みに頼らず、数えるのはフック、書くのは次の会話の秘書、と分けた。ターミナルを急に閉じても、その前の返事のときに一覧に入っているので漏れない。
- **フックは読むだけ**: 書くのは一覧のファイルだけ。一覧は機械用の帳簿なので、記憶のフォルダの外（`~/.copilot/`）に置く。
- **邪魔をしない**: 何も出力せず、エラーでも黙って終わる（エラーは `%TEMP%\fumi-hook.log` に残る）。
- **確かめたこと**（ダミーの記録で）: 書かずに3往復 → 入る。`edit` で書いた・`Add-Content` で書いた・相対パスで書いた → 入らない。読んだだけ → 入る。1往復だけ → 入らない。あとで書いた → 外れる。Copilot と同じく PowerShell の中から呼んでも、渡された内容が届く。渡された内容が空や壊れていても、一番新しい会話を見て、黙って終わる。1.1 MB の記録で 0.9 秒（起動を含む）。
- **確かめていないこと**: 本物の Copilot CLI が、このフックを呼んで正しく働くか（`~/.copilot/hooks/*.json` の `agentStop` と `sessionEnd` が呼ばれ、内容が標準入力で渡ることは、作者が別に Copilot CLI 1.0.112 で確かめている）。

## トークンの使い方

記憶はどれも md で、秘書が要点だけを書く（会話の写しではない）。索引と未記録の一覧は機械用で、全体をコンテキストに読み込むことはない。

| 場面 | 読む量（日本語はおよそ1文字＝1トークン） |
|---|---|
| 指示の文書（毎回自動で読まれる） | 約6千5百字 |
| 会話の最初の要約3つ | 最初は数千字。上限いっぱい（60＋100＋120行）でも約1万1千字 |
| 会話の最初のログ | 3日分の見出しと「次にやること」の行だけ。全体は必要なときだけ開く |
| ログを探す（1回、`-Memory`） | 当たった話題だけ。10話題×見出しと8行（1話題600字まで）で、約6千字まで。ログのファイルは開かない |
| 過去の会話を探す（1回、ログに無かったとき） | 20件×約200字で、約4千字まで。言い換えは3回まで |
| 未記録の会話を起こす | 1件1万5千字まで、1回の会話の最初に2件まで |

出力（秘書が書く量）:

| 場面 | 出力 |
|---|---|
| ログに新しい話題を足す | 200〜400字ほど。末尾に足すだけで、今ある中身は出さない |
| 同じ話題が進んだ | 変わった1行の前と後だけ |
| 要約に1件足す・直す | 1行分 |
| フック、索引づくり | 0（AI を使わない） |

書くのは1回の返事につき1回まで。1回の会話で数回書いても、数千字ほどに収まる。ファイル全体を書き直すと、1日10話題のログで毎回2千〜3千字になるので、それはさせない。

量を抑えるための決まり:

- 要約に行数の上限を付け、超えそうならまとめる。ログは1話題5行まで。
- 思い出すときは、ログのファイルを開かず、`-Memory` で当たった話題だけを読む。1年分（300日、3000話題、6 MB）のダミーのログで、どの日にもある言葉でも約4千5百字・0.2秒で返った。
- 探すのは、過去を指されたときと、その会話で初めて出た作業名などのときだけ。同じ会話で一度探した話題は探し直さない。
- 探した結果と `-All` の出力には上限を付ける。

## Copilot CLI にもともとある記憶との関係

Copilot CLI には `/memory`（Copilot Memory、会話をまたいで事実を覚える機能）が既定でオンで入っている。こちらと併用できるが、役割が違う。

| | Copilot Memory（もともと） | Fumi の記憶 |
|---|---|---|
| 置き場所 | GitHub 側。リポジトリの記憶は、そのリポジトリを使う人全員で共有される | 手元のフォルダ |
| 見る・直す | GitHub の設定画面 | エディタや Obsidian で、ふつうのノートとして |
| 向いているもの | リポジトリの中のコードの事実 | 問い合わせ、調整、雑務など、リポジトリに属さない仕事の経緯と約束 |
| 組織の設定 | 組織の設定で止められていることがある | 影響を受けない |

仕事の多くがリポジトリの外にあるので、Fumi の記憶を正にする。Copilot Memory はそのままでよい。仕事の内容を GitHub 側に置けない環境なら、`/memory off` で止める。

## 入れる

[SETUP.md](SETUP.md) の通りに行う（AI に「SETUP.md に従って、Fumi をセットアップして」と頼めばよい）。手で入れるときも同じ手順で、要点は次の通り。

- 指示の文書は、すでにある `~/.copilot/copilot-instructions.md` を上書きしない。目印の範囲を末尾に足す（SETUP.md 4-3 のコマンド）。
- スキルとフックは `~/.copilot/skills/`、`~/.copilot/hooks/` にコピーする。そこにあるほかのフックはそのままでよい（フックは並んで動く）。
- `~/.copilot/fumi.json` に、記憶のフォルダの場所（`memory_dir`）を書く。
- 記憶のフォルダが立ち上げる場所の外にあると、読み書きのたびに許可を求められる。毎回なら「このフォルダを覚える」を選ぶか、`copilot --add-dir <記憶のフォルダ>` で立ち上げる。
- PowerShell のスクリプトの実行が組織の設定で止められた環境では、スキルの検索とフックは動かない。そのときも、記憶の読み書き（指示の文書）は動く。

## 試す

1. `copilot` を立ち上げて、「私の呼び方は〇〇。覚えておいて」と言う。`USER.md` に書かれるか見る。
2. 何か一つ作業の話をして、「〇〇に決めた」と言う。`memory/` の今日のファイルに書かれるか見る。
3. Copilot を閉じて、立ち上げ直す。「前に何を決めたっけ？」と聞いて、日付付きで答えるか見る。
4. ログに書いていないはずの、前の会話の細かいこと（「さっきの会話で言った〇〇って何だっけ」）を聞き、`session-search` で探して答えるか見る。
5. 「それは忘れて」と言って、消えるか見る。
6. 自作の道具を一つ「〇〇は △△ にある。〜のときに使って」と教え、`TOOLS.md` に書かれるか見る。立ち上げ直して、その場面の依頼をし、言わなくても使うか見る。
7. 書き忘れの見張り: 「この会話はログに書かないで」と頼んで、雑談でない話を3往復する。`~/.copilot/fumi-pending.json` にその会話が入るか見る。閉じて立ち上げ直し、「前の会話を1件、ログに起こしました」と言われ、一覧から消えるか見る。

## TOOLS.md に書くもの

- **自作の CLI や exe、スクリプト、組織の中の Web ツール、よく使う共有フォルダ**: Copilot が自分では見つけられないので、場所・使う場面・使い方・注意を書く。
- **スキルと MCP サーバー**: Copilot が自分で見つけるので、場所は要らない。どの場面で使うかだけを書く。最初に作るとき、その PC に入っているものを、それぞれの説明から使う場面付きで並べる（SETUP.md 4-4）。
- **注意**: 読むだけの道具は「確認なしで使ってよい」、ファイルや外のものを書き換える道具は「確認してから」と書く。分からないものは「確認してから」にしておく。

## 同じ会話をそのまま続けたいとき

Copilot CLI 自体の機能で、前の会話をそのまま開き直せる。

- `copilot --continue`: 直前の会話を開き直す
- `copilot --resume`: 一覧から選ぶ。会話の中で `/rename 見積もり` のように名前を付けておけば、`copilot --resume 見積もり` で開ける

案件 A と B を行き来するときは、案件ごとに名前を付けた会話を開き直すと混ざらない。Fumi の記憶は、会話を変えても覚えておくためのもの。両方使える。

## これから

記憶の次に、次の機能を足していく予定。

- 受信箱: 突然の依頼を分けずに入れておき、あとでまとめて仕分ける
- リマインダーとお知らせ: 決めた時刻や、頼まれた作業が終わったときに知らせる（常駐する Obsidian のプラグインと受け渡す）
- 日報・週報: 記録から下書きを作る
- 状況の確認: 何を見張り、いつ声をかけるかを決めておき、聞かれたら答える
- スキルを育てる: 繰り返している作業や、直された進め方から、新しいスキルを提案する
